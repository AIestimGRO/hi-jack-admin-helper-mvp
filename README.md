# Hi Jack Club Admin Helper

Текущая версия: **2.0**.

Отдельный мобильный сервис для администраторов Hi, Jack Club: поиск клиента, QR по телефону, преференции и полный журнал операций.

## Что входит в MVP

- аккаунты с логином/PIN, роли `admin` и `master_admin`, защищённая cookie-сессия и CSRF;
- импорт CSV (`;`, `,`, UTF-8, CP1251) и XLSX с предпросмотром и сопоставлением колонок;
- обновление клиентов по нормализованному телефону или App ID без создания дублей;
- поиск по телефону, имени, никнейму, username, App ID и Telegram ID;
- QR, содержащий строго 10 цифр `phone_local`;
- ФриЭнтри, ФриРеЭнтри, ФриАдон и процент скидки на Бар&Кальян;
- мастер-раздел для создания, переименования, сортировки и безопасного отключения преференций;
- создание администраторов, смена PIN и отдельный аудит действий мастер-админа;
- публичный мобильный квиз на `quiz.hijackpoker.ru` с вопросами по одному на экран;
- визуальный мастер-конструктор вопросов, вариантов, правильных ответов и баллов;
- единый серверный таймер на прохождение всего теста;
- идентификация до первого вопроса по телефону или Telegram username, создание отсутствующего клиента со статусом «Новый» и первой кампанией привлечения;
- сохранение активной попытки после каждого ответа, продолжение с того же вопроса и неизменного серверного дедлайна после закрытия страницы;
- настраиваемый лимит попыток кампании (по умолчанию 3), ручная дополнительная попытка и завершение зависшей попытки из карточки клиента;
- подтверждение личности через Telegram Login или одноразовый код на email; SMS не используется;
- уникальные коды наград с периодом действия, погашением администратором и отдельным журналом;
- праздничная анимация и персональное сообщение о выигрыше либо поддерживающий экран при недоборе баллов;
- защищённая админка результатов, статистика и CSV-экспорт;
- простой табличный список результатов с отдельной подробной страницей каждого прохождения;
- расписание активности каждой кампании с точностью до минуты и настраиваемым часовым поясом;
- атомарное начисление/списание без отрицательного баланса;
- карточка и глобальный журнал операций с CSV-экспортом;
- полностью адаптивный интерфейс: карточки, формы, навигация и квиз перестраиваются под смартфон, узкое окно, планшет и компьютер;
- systemd, Nginx, HTTPS-инструкция и ежедневный бэкап за 14 дней.

## Локальный запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env
# Заполните HJC_MASTER_LOGIN, HJC_ADMIN_PIN, HJC_SECRET_KEY и публичные URL
set -a; source .env; set +a
.venv/bin/uvicorn app.main:app --reload --host 127.0.0.1 --port 8090
```

Откройте `http://127.0.0.1:8090`. Для локального HTTP поставьте `HJC_SECURE_COOKIE=false`; на VPS должно быть `true`.

Стили и JavaScript подключаются с номером версии из файла `VERSION`. После обновления браузер получает согласованный комплект интерфейса без смешивания старых скриптов с новыми страницами.

## Тесты

```bash
.venv/bin/pytest -q
```

SQLite-схема создаётся автоматически при старте. Полная инструкция VPS: [deploy.md](deploy.md).

При первом запуске создаётся мастер-аккаунт с логином `HJC_MASTER_LOGIN` и PIN из `HJC_ADMIN_PIN`. После этого аккаунты хранятся в SQLite, а изменение PIN в `.env` не перезаписывает существующий мастер-аккаунт.

## Важные правила данных

- `phone_local` — только 10 цифр, без `7`/`8`; именно эта строка помещается в QR.
- Если один телефон и App ID указывают на разные существующие карточки, импорт пропускает конфликт вместо опасного объединения.
- App ID, Telegram ID и Referrer ID сохраняются, но показаны в сворачиваемом вторичном блоке.
- Все изменения преференций проходят внутри транзакции и записываются в `preference_log`.
- Используемая преференция не удаляется: мастер может отключить её, сохранив балансы и историю.
- Обычный администратор не имеет доступа к мастер-странице и мастер-API.
- Публичный поддомен не открывает базу клиентов или админские API.

## Квиз

Публичные ссылки:

```text
https://quiz.hijackpoker.ru/
https://quiz.hijackpoker.ru/quiz?campaign=honor_more&referrer_id=485&source=tg_post
```

Файл `data/quiz_questions.json` используется только для первоначального переноса стартовых вопросов в SQLite. После первого запуска вопросы создаются и редактируются через «Мастер → Кампании квиза → Редактор вопросов». Если у активной кампании нет собственных опубликованных вопросов, используются вопросы `default`.

Поддерживаются:

- `single_choice` — один вариант; мастер может отметить один правильный ответ;
- `multi_choice` — несколько вариантов; ответ засчитывается только при полном совпадении набора;
- `text` — свободный ответ, который не участвует в автоматическом подсчёте.

Вопрос заполняется вместе со всеми вариантами и сохраняется одной кнопкой — отдельные действия для черновика и публикации не нужны. Сохранённый вопрос сразу участвует в квизе. Для вопроса с выбором нужно добавить минимум два варианта и отметить правильные ответы. Каждому проверяемому вопросу назначаются баллы. В настройках кампании указываются проходной порог, бонусная преференция, количество бонусов и общее число секунд на прохождение теста. Нулевой лимит полностью отключает таймер. Порог `0` означает бонус за сам факт прохождения и сохраняет старое поведение.

Основной редактор сохраняет текст вопроса, все варианты и правильные ответы одной кнопкой. Для изменения достаточно раскрыть нужный вопрос в списке, отредактировать его и нажать «Сохранить изменения». Поля баллов и обязательности находятся в «Дополнительных настройках», а перемещение, дублирование и удаление — в скрытом меню второстепенных действий.

Для массового добавления откройте «Добавить несколько вопросов текстом». Первая строка блока — вопрос, строки со `*` — правильные ответы, строки с `-` — неправильные. Между вопросами нужна пустая строка:

```text
Какая комбинация старше?
- Стрит
* Флеш
- Тройка

Выберите красные масти
* Червы
* Бубны
- Пики
```

Одна звёздочка создаёт вопрос с одиночным выбором, несколько звёздочек — с множественным. Импорт выполняется целиком: при ошибке в одном блоке ни один вопрос из вставки не сохраняется.

До старта участник указывает номер телефона или Telegram username. Имя и никнейм необязательны. Если карточки нет, она создаётся со статусом `new`, кодом первой кампании, источником и Referrer ID. Одна активная попытка привязана к клиенту и кампании: повторное открытие ссылки возвращает тот же набор вопросов, сохранённые ответы, текущий вопрос и исходный серверный дедлайн. Закрытие вкладки не останавливает таймер и не возвращает использованную попытку.

По умолчанию разрешено 3 попытки, но лимит настраивается отдельно для каждой кампании. После успешного прохождения новые попытки блокируются. Администратор может дать дополнительную попытку или завершить активную, мастер-администратор — сбросить счётчик попыток. Компактная сводка участия сохраняется независимо от удаления подробных ответов, поэтому недельная очистка не восстанавливает лимит.

После старта сервер фиксирует единый дедлайн всей попытки. Участник переходит между вопросами кнопками «Назад» и «Далее» и может изменить предыдущий ответ; каждое изменение сохраняется на сервере. Когда общее время заканчивается, попытка считается неуспешной. Подмена времени на устройстве не продлевает серверный дедлайн.

Для каждого результата сохраняются баллы, количество правильных ответов, достижение порога и снимок текста вопросов/вариантов на момент прохождения. Поэтому дальнейшее редактирование квиза не изменяет старые результаты. Правильные ответы никогда не передаются публичному API. Стартовые и финальные тексты редактируются в настройках кампании и поддерживают переменные `{bonus}`, `{score}`, `{max_score}`, `{correct_count}`, `{max_correct_count}`, `{attempts_used}`, `{max_attempts}`.

При достижении порога система выдаёт уникальный код вида `HJ-XXXX-XXXX`. Код может действовать до конца текущего дня по Москве, заданное число часов/дней, в фиксированном интервале или бессрочно. До погашения бонус не попадает на баланс клиента. После применения кода администратором бонус начисляется в обычную преференцию и уже не сгорает. Статусы кода: `issued`, `used`, `expired`, `cancelled`.

Результаты доступны всем авторизованным администраторам на `/admin/quiz-results`.

Общий экран результатов показывает только телефон, username, баллы, прохождение порога, состояние бонуса, дату и название квиза. Клик по строке открывает отдельную страницу со всеми данными и ответами участника.

В настройках кампании поля «Активен с» и «Активен до» задают период приёма новых прохождений. Оба поля необязательны. Часовой пояс берётся из `HJC_TIMEZONE` (по умолчанию `Europe/Moscow`). До начала участник увидит время старта, после окончания — сообщение о завершении квиза. Уже начатая в разрешённый период попытка может быть закончена.

Защита строится на клиенте и кампании, а не только на IP: текущая попытка возобновляется, число начатых попыток сохраняется, а успешное получение награды блокирует повтор. HMAC-хэш IP используется только для ограничения массовых запросов; исходный IP не хранится. Для более строгих кампаний мастер включает обязательное подтверждение через Telegram или email.

## Telegram и email без SMS

Telegram Login включается переменными `HJC_TELEGRAM_CLIENT_ID` и `HJC_TELEGRAM_CLIENT_SECRET`, которые выдаёт BotFather в разделе Web Login после регистрации разрешённых URL. Используется актуальный OpenID Connect Authorization Code Flow с PKCE; сервер проверяет подпись ID token, issuer, audience и срок действия по официальному Telegram JWKS. Постоянный `sub` сохраняется как `telegram_user_id`, а изменяемый username остаётся контактным полем. Email-подтверждение включается SMTP-переменными из `.env`; шестизначный код действует 10 минут по умолчанию. Телефон по SMS не подтверждается и SMS-провайдер приложению не нужен.

Кампанию нельзя переключить в режим обязательного подтверждения, пока не настроен хотя бы один из способов — Telegram или email.

## Каркас 4:14 и личный кабинет

В мастер-разделе кампании разделены на обычные и `4:14` (`campaign_type=classic/daily_414`). Новый выпуск `4:14` по умолчанию планируется на ближайшие 18:14 по времени `HJC_TIMEZONE` и завершается в полночь. Для него сервер фиксирует 10 собственных опубликованных вопросов, одну попытку на аккаунт и общий лимит 254 секунды. Участник должен войти в личный кабинет; после входа он возвращается к исходной ссылке игры.

Игровой путь `4:14` отделён от обычного квиза правилами: вопросы идут только вперёд, сохранённый ответ нельзя изменить, этапы размечаются как `ПРЕФЛОП` (1–2), `ФЛОП` (3–5), `ТЁРН` (6–8) и `РИВЕР` (9–10), перед десятым вопросом показывается отдельный экран `RIVER`. Результат хранит число правильных ответов, точное время, участие в главном призе, начисленные JACKCOIN и текущую серию дней. В отбор на финальный стол попадают участники, начавшие игру в первые 5 минут; сам синхронный финал запускается на общей серверной отметке `T+9:14`. Более поздний участник может пройти выпуск до окончания кампании, получить JACKCOIN и продолжить серию, но его результат не входит в основной розыгрыш.

Экономика `4:14` настраивается отдельно для каждого выпуска. Значения по умолчанию: 5 JACKCOIN за каждый правильный ответ, 10 за завершение выпуска, ещё 20 за 10/10. Бонусы за серию: 3 дня — 10, 7 дней — 30, 14 дней — 70, 30 дней — 150 JACKCOIN. Начисления проводятся через идемпотентный `jackcoin_ledger`, поэтому повторный запрос завершения не удваивает баланс.

Личный кабинет включается только флагом `HJC_MEMBER_PORTAL_ENABLED=true` и доступен на `/account`. Регистрация последовательно требует принятия двух версионированных документов, телефона, почты и пароля длиной не менее 6 символов с хотя бы одной буквой. Почта подтверждается одноразовым кодом; пароль хранится только как PBKDF2-хэш. После создания аккаунта участнику предлагается подключить постоянный Telegram ID через OIDC, чтобы объединить достижения из Hi Jack UP!; экран можно пропустить и вернуться к подключению из личного кабинета. Сессии личного кабинета являются отдельными отзывными серверными сессиями и по умолчанию действуют 30 дней (`HJC_MEMBER_SESSION_DAYS`).

В кабинете есть разделы «Главная», «Квизы», центральный игровой раздел `HJ`, «Хранилище» и «Профиль». Главная ставит на первый план баланс JACKCOIN, актуальную игру, доступные по балансу награды и активные карты; личные данные находятся в профиле. `HJ` открывает JACKSIDE-рейтинг за сегодня, последние 30 дней и всё время, компактную личную статистику и отдельную вкладку последнего импортированного рейтинга Hi Jack App. JACKSIDE points считаются отдельно от JACKCOIN: один балл за правильный ответ завершённой основной части, два за финальный стол и пять за победу. Формулы, границы периодов и определения административных метрик описаны в `docs/jackside-ratings-and-analytics.md`. Раздел `THE VAULT` показывает опубликованный каталог и выполняет атомарный обмен JACKCOIN на цифровую `JACK CARD`. Сначала карта отображается без реквизитов погашения. После явной активации участником на 10 минут появляются четырёхзначный код и QR: длительность задаётся `HJC_VAULT_ACTIVATION_MINUTES`, короткий код уникален среди активных карт, а QR использует отдельный длинный внутренний токен. Оба способа ведут к одному одноразовому погашению через защищённую админскую страницу; окончательное списание выполняется отдельным POST с админской авторизацией и CSRF. Если карту не погасили, код и QR закрываются, но сама награда остаётся активной и может быть активирована повторно. Ограниченный тираж резервируется в той же транзакции, что и списание JACKCOIN; отмена активной купленной карты мастер-администратором возвращает списанный баланс.

Награде можно назначить одну из 10 встроенных Lottie-анимаций или загрузить собственную. Рекомендуемый холст — `512×512 px`, прозрачный фон, объект в центральной области около `420×420 px`, цикл `1,5–3 секунды`. Поддерживаются Lottie JSON и `.lottie` до 1 МБ, animated WebP до 1,5 МБ, GIF до 2 МБ и PNG до 1 МБ. Файл проверяется по содержимому; внешние URL внутри Lottie запрещены. Пользовательские файлы хранятся рядом с рабочей базой в каталоге `reward-media`, а встроенный web-player и WASM поставляются локально без зависимости от CDN.

Админский интерфейс использует единый адаптивный рабочий каркас. На смартфоне частые разделы доступны из нижней навигации, полный набор функций — из меню второго уровня; на главной вынесены поиск клиента, выдача JACK CARD и результаты квизов. Цветовые акценты имеют смысл раздела: бирюзовый — клиенты, синий — квизы, золотой — хранилище, медный — мастер-настройки.

Для выпуска `4:14` мастер может выбрать главный приз из активного каталога `THE VAULT`. Выбор фиксируется в записи конкретного финального стола и не меняется при последующем редактировании кампании. После определения единственного победителя цифровая карта выдаётся автоматически и идемпотентно. Ошибка выдачи (например, закончился тираж) отображается в `THE VAULT`; мастер может устранить причину и повторить выдачу вручную.

При публикации новой версии юридического документа участник должен принять её перед следующим входом в кабинет.

## Сроки хранения

- незавершённая попытка хранится минимально для возобновления и лимита; просроченная подробная запись удаляется через 7 дней;
- подробные завершённые прохождения и ответы — 7 дней;
- код награды — минимум 14 дней и никогда не удаляется раньше окончания собственного срока действия;
- начисленный клиенту бонус и `preference_log` не сгорают и хранятся бессрочно;
- журнал событий кодов — минимум 31 день;
- просроченные коды почты и серверные сессии личного кабинета очищаются автоматически;
- компактная сводка попыток остаётся, чтобы очистка подробностей не обнуляла лимит;
- резервные копии — 14 дней.

Очистка запускается автоматически не чаще одного раза в сутки. Сроки можно изменить через `HJC_QUIZ_DETAIL_RETENTION_DAYS`, `HJC_REWARD_RETENTION_DAYS` и `HJC_ACTION_LOG_RETENTION_DAYS`.
